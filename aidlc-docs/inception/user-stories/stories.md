# User Stories - MindEcho

## ストーリー構成方針
- **分解アプローチ**: ユーザージャーニーベース（アップロード→設問→感情選択→生成のフローに沿って分解）
- **受け入れ基準**: 標準（正常系・異常系を含む4〜6個の基準）
- **メディア優先度**: 画像 > 音楽 > 漫画 > 小説
- **MVPスコープ**: パーソナライゼーション（FR-6）はMVP対象外、後続フェーズで対応

---

## Journey 1: アカウント作成・ログイン

### US-1.1: ユーザー登録
**As a** 新規ユーザー  
**I want to** メールアドレスとパスワードでアカウントを作成したい  
**So that** MindEchoの全機能を利用し、自分のデータを保存できる

**Acceptance Criteria:**
1. メールアドレスとパスワード（8文字以上、英数字混合）で登録が完了すること
2. 既に登録済みのメールアドレスではエラーメッセージが表示されること
3. 無効なメールアドレス形式ではバリデーションエラーが表示されること
4. 登録完了後、自動的にログイン状態となりホーム画面へ遷移すること

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have

---

### US-1.2: ログイン
**As a** 登録済みユーザー  
**I want to** メールアドレスとパスワードでログインしたい  
**So that** 自分のアカウントにアクセスし、過去のデータを利用できる

**Acceptance Criteria:**
1. 正しいメールアドレスとパスワードでログインが成功すること
2. 誤ったパスワードでは「メールアドレスまたはパスワードが正しくありません」とエラーが表示されること
3. 未登録のメールアドレスでも同一のエラーメッセージが表示されること（セキュリティ）
4. ログイン後、ホーム画面へ遷移すること

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have

---

### US-1.3: パスワードリセット
**As a** パスワードを忘れたユーザー  
**I want to** メールアドレスを入力してパスワードをリセットしたい  
**So that** アカウントに再度アクセスできる

**Acceptance Criteria:**
1. 登録済みメールアドレスを入力するとリセットメールが送信されること
2. 未登録メールアドレスでも「メールを送信しました」と表示されること（セキュリティ）
3. リセットリンクから新しいパスワードを設定できること
4. リセットリンクは有効期限（24時間）を持つこと

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Should Have

## Journey 2: メディアアップロード

### US-2.1: 画像アップロード
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** スマホやPCから画像ファイルをアップロードしたい  
**So that** 画像に対する自分の感想文を生成してもらえる

**Acceptance Criteria:**
1. JPEG, PNG, WebP, GIF形式のファイルをアップロードできること
2. ファイルサイズ上限（10MB）を超えた場合はエラーメッセージが表示されること
3. 非対応形式のファイルではエラーメッセージが表示されること
4. アップロード中はプログレスバーが表示されること
5. アップロード完了後、プレビューが表示されること

**Persona**: ユキ、ミサキ  
**Priority**: Must Have (P1)

---

### US-2.2: 音楽アップロード
**As a** ミサキ（内省記録ユーザー）  
**I want to** 音楽ファイルをアップロードしたい  
**So that** 楽曲に対する感想を言語化してもらえる

**Acceptance Criteria:**
1. MP3, WAV, FLAC, AAC形式のファイルをアップロードできること
2. ファイルサイズ上限（50MB）を超えた場合はエラーメッセージが表示されること
3. 非対応形式のファイルではエラーメッセージが表示されること
4. アップロード中はプログレスバーが表示されること
5. アップロード完了後、再生プレーヤーでプレビュー再生できること

**Persona**: ユキ、ミサキ、リョウ  
**Priority**: Must Have (P2)

---

### US-2.3: 漫画ページアップロード
**As a** タケシ（コンテンツレビュアー）  
**I want to** 漫画のページ画像をアップロードしたい  
**So that** 漫画の感想・レビュー文を効率的に作成したい

**Acceptance Criteria:**
1. JPEG, PNG, WebP形式の漫画ページ画像をアップロードできること
2. 複数ページを一度にアップロードできること（最大10ページ）
3. ファイルサイズ上限（1ページあたり10MB）を超えた場合はエラーが表示されること
4. アップロード完了後、ページのサムネイルプレビューが表示されること
5. メディア種別として「漫画」が自動判別または手動選択できること

**Persona**: タケシ  
**Priority**: Should Have (P3)

---

### US-2.4: 小説・テキスト入力
**As a** タケシ（コンテンツレビュアー）  
**I want to** 小説の一節をテキストとして貼り付け、またはファイルでアップロードしたい  
**So that** 小説に対する読後感をレビュー記事として生成したい

**Acceptance Criteria:**
1. テキストエリアにプレーンテキストを直接貼り付けできること（最大10,000文字）
2. TXT, PDF形式のファイルをアップロードできること
3. ファイルサイズ上限（5MB）を超えた場合はエラーが表示されること
4. 入力/アップロード完了後、テキストのプレビューが表示されること
5. 文字数が不足（50文字未満）の場合は警告が表示されること

**Persona**: タケシ、ミサキ  
**Priority**: Should Have (P4)

---

## Journey 3: メディア解析

### US-3.1: メディア解析の完了通知
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** アップロードしたメディアのAI解析が完了したことを知りたい  
**So that** 次のステップ（コンテクスト設問）に進める

**設計意図**: AI解析結果の詳細はこの時点ではユーザーに表示しない。解析結果を先に見せると、ユーザーの素の感情がAIの解釈に引きずられバイアスがかかるため。解析結果は最終的な文章出力時に「リザルト」としておまけ表示する（US-6.2参照）。

**Acceptance Criteria:**
1. アップロード完了後、自動的に解析が開始されること
2. 解析中はローディングインジケーターと「解析中...」のメッセージが表示されること
3. 解析完了後、「解析が完了しました」の通知のみ表示されること（解析結果の詳細は表示しない）
4. 解析完了後、自動的にコンテクスト設問画面に遷移すること
5. 解析失敗時はリトライボタンとエラーメッセージが表示されること

**対応メディア**: 画像(P1)、音楽(P2)、漫画(P3)、小説(P4)  
**Persona**: ユキ、タケシ、ミサキ、リョウ  
**Priority**: Must Have

---

## Journey 4: メディアコンテクスト入力

### US-4.1: コンテクスト設問への回答
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** メディアに関する設問（選択式）に答えることで、AIに追加のコンテクストを提供したい  
**So that** より自分の状況に合った、解像度の高い文章が生成される

**Acceptance Criteria:**
1. メディア解析完了後、3〜5問の選択式設問が自動表示されること
2. 設問はメディアの種類と解析結果に応じて動的に生成されること
3. 各設問は選択肢（A〜D + その他）をタップ/クリックで回答できること
4. 「その他」を選択した場合、短い自由記述欄が表示されること
5. 全設問への回答は必須ではなく、スキップ可能であること

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have

---

### US-4.2: 自由記述による補足入力
**As a** タケシ（コンテンツレビュアー）  
**I want to** 設問の最後に自由記述で追加情報を入力したい  
**So that** 選択肢にない独自の視点や文脈を文章生成に反映できる

**Acceptance Criteria:**
1. 設問の最後に自由記述テキストエリアが表示されること
2. 自由記述は任意入力（スキップ可能）であること
3. 入力可能な文字数の上限（500文字）が表示されること
4. 入力した内容が文章生成の追加コンテクストとして活用されること

**Persona**: タケシ、ミサキ  
**Priority**: Must Have

---

## Journey 5: 感情選択

### US-5.1: 感情選択肢の選択
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** AIが提示する感情選択肢の中から、自分が感じた感情を選びたい  
**So that** 自分の感情を言語化する手間なく、AIに的確な文章を生成してもらえる

**Acceptance Criteria:**
1. メディア解析結果とコンテクスト入力に基づき、3〜5個の感情選択肢が表示されること
2. 感情選択肢はタップ/クリックで選択できること
3. 複数の感情を同時に選択できること
4. 選択した感情には視覚的なハイライトが表示されること
5. 最低1つの感情が選択されないと次のステップに進めないこと

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have

---

## Journey 6: 文章生成

### US-6.1: 出力形式の選択
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** 生成する文章の出力形式（SNS投稿・日記・レビュー）を選びたい  
**So that** 用途に合った長さ・トーンの文章が得られる

**Acceptance Criteria:**
1. SNS投稿（140〜280文字）、日記・メモ（300〜500文字）、レビュー記事（500〜1000文字）の3形式が選択可能であること
2. 各形式の説明と想定文字数が表示されること
3. デフォルトはSNS投稿が選択されていること
4. 形式選択は1つのみ可能であること

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have

---

### US-6.2: 文章生成と結果表示
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** 感情選択と出力形式を元にAIが文章を生成し、結果を確認したい  
**So that** すぐにSNSに投稿できる文章を手に入れられる

**Acceptance Criteria:**
1. 「生成」ボタンをタップ/クリックすると文章生成が開始されること
2. 生成中はローディングインジケーターが表示されること
3. 生成結果が5秒以内に表示されること
4. 生成された文章が選択した出力形式の文字数範囲に収まっていること
5. 生成文の下部に「AI解析リザルト」としてメディア解析結果（抽出された特徴量）がおまけ表示されること
6. 生成失敗時はリトライボタンとエラーメッセージが表示されること

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have

---

### US-6.3: 文章の編集
**As a** タケシ（コンテンツレビュアー）  
**I want to** 生成された文章を手動で編集・微調整したい  
**So that** 自分のスタイルに合った最終的な文章に仕上げられる

**Acceptance Criteria:**
1. 生成された文章がテキストエリアに表示され、直接編集できること
2. 編集中の文字数がリアルタイムでカウント表示されること
3. 元の生成文に戻す「リセット」ボタンがあること
4. 編集内容は自動保存されること

**Persona**: タケシ、ミサキ  
**Priority**: Should Have

---

### US-6.4: 文章の再生成
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** 生成結果に満足しない場合、再生成（リトライ）したい  
**So that** より良い文章が得られるまで試行錯誤できる

**Acceptance Criteria:**
1. 「再生成」ボタンが表示されていること
2. 再生成すると前回とは異なる文章が生成されること
3. 過去の生成結果に戻ることはできないこと（最新のみ保持）
4. 再生成回数に合理的な制限（セッションあたり10回）があること

**Persona**: ユキ  
**Priority**: Must Have

---

### US-6.5: 文章のコピー
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** 生成された文章をワンタップでクリップボードにコピーしたい  
**So that** 任意のアプリに貼り付けて利用できる

**Acceptance Criteria:**
1. 「コピー」ボタンが文章表示エリア付近に表示されていること
2. ボタンタップでクリップボードにコピーされること
3. コピー成功時に「コピーしました」のトースト通知が表示されること
4. 編集後の文章もコピー対象となること

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have

---

### US-6.6: SNSへの直接投稿
**As a** ユキ（カジュアルSNSユーザー）  
**I want to** 生成された文章を各種SNSに直接投稿したい  
**So that** コピー＆ペーストの手間なく、ワンタップでSNSにシェアできる

**Acceptance Criteria:**
1. 文章表示エリアにSNS共有ボタン（X/Twitter、Instagram、Threads、Bluesky等）が表示されること
2. ボタンタップで各SNSの投稿画面（Web Intent / シェアAPI）が開き、生成文が自動入力されること
3. 各SNSの文字数制限を超える場合は、投稿前に警告が表示されること
4. SNS連携はユーザーのSNSアカウントとのMindEchoアカウントの紐付けを必須としないこと（Web Intent方式）
5. モバイルブラウザではOSのネイティブシェア機能（Web Share API）も利用可能であること

**Persona**: ユキ、リョウ  
**Priority**: Must Have

## Journey 7: データ管理・プライバシー

### US-7.1: 生成履歴の閲覧
**As a** ミサキ（内省記録ユーザー）  
**I want to** 過去に生成した文章の一覧を閲覧したい  
**So that** 過去の感動を振り返ることができる

**Acceptance Criteria:**
1. 生成日時、メディア種別、出力形式が一覧表示されること
2. 一覧から選択して詳細（生成文、選択した感情、メディアプレビュー）を確認できること
3. 新しいものから順に表示されること
4. ページネーションまたは無限スクロールで過去データにアクセスできること

**Persona**: ミサキ、タケシ  
**Priority**: Should Have

---

### US-7.2: データの削除
**As a** ミサキ（内省記録ユーザー）  
**I want to** 特定の生成履歴または全データを削除したい  
**So that** プライバシーを管理し、不要なデータを消去できる

**Acceptance Criteria:**
1. 個別の生成履歴を削除できること
2. 全データの一括削除が可能であること
3. 削除前に確認ダイアログが表示されること
4. 削除したデータは復元できないことが明示されること
5. 一括削除はメディアファイルを含むすべての関連データが対象であること

**Persona**: ミサキ、タケシ  
**Priority**: Must Have (GDPR準拠)

---

### US-7.3: データエクスポート
**As a** タケシ（コンテンツレビュアー）  
**I want to** 自分の生成データをエクスポートしたい  
**So that** 手元にバックアップを保持できる

**Acceptance Criteria:**
1. JSON形式でデータをエクスポートできること
2. エクスポート対象は生成文章、感情選択履歴、コンテクスト入力を含むこと
3. エクスポート処理中はプログレスバーが表示されること
4. エクスポート完了後、ファイルがダウンロードされること

**Persona**: タケシ  
**Priority**: Should Have (GDPR準拠)

---

### US-7.4: アカウント削除
**As a** ユーザー  
**I want to** アカウントと全関連データを完全に削除したい  
**So that** サービスの利用を完全に終了できる

**Acceptance Criteria:**
1. アカウント設定画面から削除を実行できること
2. パスワード再入力による本人確認が必要であること
3. 削除前に「この操作は取り消せません」の確認ダイアログが表示されること
4. アカウント削除時に全関連データ（メディア、生成履歴、ユーザー情報）が削除されること
5. 削除完了後、ログアウトされトップページへ遷移すること

**Persona**: ユキ、タケシ、ミサキ  
**Priority**: Must Have (GDPR準拠)
