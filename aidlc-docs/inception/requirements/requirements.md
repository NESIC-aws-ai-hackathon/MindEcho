# Requirements Document - MindEcho (感情言語化支援サービス)

## Intent Analysis Summary

| 項目 | 内容 |
|---|---|
| **User Request** | 感情言語化支援サービス "MindEcho" の開発。メディア解析 → 感情選択 → 文章生成のパイプラインを持つWebアプリケーション。 |
| **Request Type** | New Project (新規プロジェクト) |
| **Scope Estimate** | System-wide (複数コンポーネントにまたがるフルスタック開発) |
| **Complexity Estimate** | Complex (AI/ML統合、マルチメディア解析、パーソナライゼーション) |

---

## 1. Functional Requirements (機能要件)

### FR-1: メディアアップロード・管理
- **FR-1.1**: ユーザーが画像ファイル（JPEG, PNG, WebP, GIF）をアップロードできること
- **FR-1.2**: ユーザーが音楽ファイル（MP3, WAV, FLAC, AAC）をアップロードできること
- **FR-1.3**: ユーザーが漫画作品のページ画像（JPEG, PNG, WebP）をアップロードできること
- **FR-1.4**: ユーザーが小説・文章作品のテキスト（プレーンテキスト貼り付けまたはファイル: TXT, PDF）を入力できること
- **FR-1.5**: アップロードされたメディアをAWS S3に保存すること
- **FR-1.6**: アップロード時にファイルサイズ・形式のバリデーションを行うこと
- **FR-1.7**: メディア種別（画像 / 音楽 / 漫画 / 小説）を自動判別またはユーザーが選択できること

### FR-2: メディアコンテクスト抽出 (Media Analysis Unit)
- **FR-2.1**: 画像から情緒的メタデータ（色彩、構図、雰囲気、被写体）を自動抽出すること（AWS Bedrock利用）
- **FR-2.2**: 音楽からリズム、テンポ、ムード、ジャンル等の特徴量を抽出すること（AWS Bedrock利用）
- **FR-2.3**: 漫画ページからコマ構成、描線スタイル、キャラクターの感情表現、ストーリーの雰囲気を抽出すること（AWS Bedrock利用）
- **FR-2.4**: 小説・文章テキストから文体、テーマ、トーン、感情的キーワード、物語のムードを抽出すること（AWS Bedrock利用）
- **FR-2.5**: 抽出結果を構造化されたJSON形式で保持すること
- **FR-2.6**: 解析処理の進捗をユーザーに表示すること

### FR-3: メディアコンテクスト入力 (Media Context Input)
- **FR-3.1**: メディア解析結果に基づき、メディアに関する補足情報を設問形式（選択式）でユーザーに提示すること
  - 例（画像の場合）: 「この画像はどのような場面ですか？」→ A) 日常風景 B) 旅行先 C) アート作品 D) 思い出の一枚 X) その他
  - 例（音楽の場合）: 「この曲をどのようなシチュエーションで聴いていますか？」→ A) 通勤中 B) 作業中 C) リラックスタイム D) 特別な瞬間 X) その他
  - 例（漫画の場合）: 「このシーンのどこに惹かれましたか？」→ A) キャラクターの表情 B) ストーリー展開 C) 演出・コマ割り D) セリフ X) その他
  - 例（小説の場合）: 「この文章のどの要素に心を動かされましたか？」→ A) 文体・表現 B) ストーリー C) キャラクター D) 世界観・情景描写 X) その他
- **FR-3.2**: 設問はメディアの解析メタデータ（色彩、雰囲気、テンポ等）に応じてAIが動的に生成すること（3〜5問程度）
- **FR-3.3**: ユーザーがタップ/クリックのみで回答できること（選択式UI）
- **FR-3.4**: 設問の最後に、任意の自由記述入力欄を設けること（例: 「他に伝えたいことがあれば自由に入力してください」）
- **FR-3.5**: 自由記述は任意（スキップ可能）とし、入力がある場合は文章生成の追加コンテクストとして活用すること

### FR-4: 感情アノテーション・インターフェース (Cognitive Mapping Unit)
- **FR-4.1**: 抽出されたメタデータおよびFR-3のコンテクスト入力に基づき、3〜5個の感情選択肢をAIが生成・提示すること
- **FR-4.2**: ユーザーがタップ/クリックのみで感情を選択できること（自由記述不要）
- **FR-4.3**: 複数の感情を同時選択可能とすること

### FR-5: ロジック・アンプリファイア - 文章生成 (Sentence Synthesis Unit)
- **FR-5.1**: 選択された感情、メディア解析結果、およびコンテクスト入力（FR-3）を組み合わせ、自然な文章を生成すること
- **FR-5.2**: 出力形式を選択可能とすること:
  - SNS投稿（短文、140〜280文字程度）
  - 個人日記・メモ（中文、300〜500文字程度）
  - レビュー記事（長文、500〜1000文字程度）
- **FR-5.3**: 生成された文章をユーザーが編集・微調整できること
- **FR-5.4**: 文章の再生成（リトライ）が可能であること
- **FR-5.5**: 生成文章をクリップボードにコピーできること
- **FR-5.6**: 生成文章を各種SNS（X/Twitter、Instagram、Threads、Bluesky等）に直接投稿（Web Intent / Web Share API）できること

### FR-6: パーソナライズド・シンクロニシティ (User Persona Tuning Unit)
- **FR-6.1**: ユーザーの過去の感情選択履歴およびコンテクスト入力履歴を記録すること
- **FR-6.2**: 過去の履歴に基づき、そのユーザーが好む文体・語彙を学習すること
- **FR-6.3**: 学習結果を次回以降の感情選択肢生成・文章生成に反映すること

### FR-7: ユーザー認証・アカウント管理
- **FR-7.1**: メールアドレス + パスワードによるユーザー登録が可能であること
- **FR-7.2**: メールアドレス + パスワードによるログインが可能であること
- **FR-7.3**: パスワードリセット機能を提供すること
- **FR-7.4**: ユーザーがアカウントを削除できること（関連データも削除）

### FR-8: データ管理・プライバシー
- **FR-8.1**: ユーザーの感情履歴・生成文章をクラウドに保存すること
- **FR-8.2**: ユーザーが自身のデータを一覧・閲覧できること
- **FR-8.3**: ユーザーが自身のデータを個別または一括で削除できること（GDPR準拠）
- **FR-8.4**: データエクスポート機能を提供すること

## 2. Non-Functional Requirements (非機能要件)

### NFR-1: パフォーマンス
- **NFR-1.1**: メディアアップロード完了後、解析結果の表示まで10秒以内（画像）、30秒以内（音楽）
- **NFR-1.2**: 感情選択後の文章生成は5秒以内
- **NFR-1.3**: ページ初期表示は3秒以内（LCP基準）

### NFR-2: スケーラビリティ
- **NFR-2.1**: 初期ターゲットは同時ユーザー~100人規模（社内PoC）
- **NFR-2.2**: 将来的なスケールアウトを考慮したアーキテクチャとすること

### NFR-3: 可用性
- **NFR-3.1**: PoC段階のため、稼働率目標は99%（月間ダウンタイム約7.2時間許容）

### NFR-4: セキュリティ
- **NFR-4.1**: パスワードはbcrypt等で適切にハッシュ化して保存すること
- **NFR-4.2**: APIエンドポイントはJWTトークンによる認証を行うこと
- **NFR-4.3**: ファイルアップロードにはファイルタイプ・サイズの検証を行うこと
- **NFR-4.4**: SQLインジェクション・XSS等の一般的な脆弱性対策を行うこと

### NFR-5: ユーザビリティ
- **NFR-5.1**: レスポンシブデザインによるモバイルブラウザ対応
- **NFR-5.2**: 直感的なUI（タップ/クリック主体の操作）
- **NFR-5.3**: 日本語UIを標準とすること

### NFR-6: 保守性
- **NFR-6.1**: コンポーネントベースのモジュラーアーキテクチャとすること
- **NFR-6.2**: AIモデル/サービスの差し替えが容易な抽象化レイヤーを設けること

## 3. Technical Architecture Decisions (技術アーキテクチャ決定事項)

| 領域 | 技術選定 | 理由 |
|---|---|---|
| **Frontend** | React (Next.js) | ユーザー指定。SSR/SSG対応、エコシステムの充実 |
| **Backend** | Python (FastAPI) | AI/ML系ライブラリとの親和性、AWS SDK (boto3) との統合容易性、非同期処理対応 |
| **AI/ML** | AWS Bedrock (Claude/Titan) | AWS統一アーキテクチャ、マネージドサービスによる運用負荷低減 |
| **Database** | Amazon RDS (PostgreSQL) | リレーショナルデータ管理、JSONB対応による柔軟なメタデータ格納 |
| **Storage** | Amazon S3 | メディアファイル保存、高耐久性・コスト効率 |
| **Authentication** | 自前実装 (JWT + bcrypt) | PoC規模のためシンプルな実装で十分 |
| **Deploy** | AWS (ECS or Lambda) | AWS統一、PoC規模ではLambda + API Gatewayが費用効率的 |

## 4. Unit Decomposition (ユニット分解)

Initial Conceptで定義された4ユニット構成を採用:

| Unit | 名称 | 責務 |
|---|---|---|
| **Unit 1** | Media Analysis Unit | マルチメディアデータの受け取り、S3保存、情緒的・客観的特徴量の抽出 |
| **Unit 2** | Cognitive Mapping Unit | 解析データに基づくコンテクスト設問の生成、自由記述入力の受付、感情選択肢の生成、ユーザー入力の正規化 |
| **Unit 3** | Sentence Synthesis Unit | 感情シードを元にした高度なレトリックを用いた文章生成 |
| **Unit 4** | User Persona Tuning Unit | ユーザー個別の感情傾向学習、出力トーンの最適化 |

加えて、横断的関心事として以下を追加:
| Unit | 名称 | 責務 |
|---|---|---|
| **Unit 0** | Auth & Core Infrastructure | ユーザー認証、DB設計、API基盤、共通ミドルウェア |

## 5. Data Flow Overview (データフロー概要)

```
User → [Upload Media] → Unit 0 (Auth) → Unit 1 (Media Analysis)
                                              ↓
                                    [Emotional Metadata]
                                              ↓
                                    Unit 2 (Cognitive Mapping)
                                              ↓
                                    [Context Questions] → User answers (選択式)
                                    [Free Text Input]  → User inputs (任意)
                                              ↓
                                    [Emotion Choices]   → User selects
                                              ↓
                                    Unit 3 (Sentence Synthesis)
                                              ↓  ← Context + Emotions + Metadata
                                    [Generated Text] → User reviews/edits
                                              ↓
                                    Unit 4 (Persona Tuning) ← learns from history
```

## 7. MVP Scope

**MVP（最小実行可能製品）の範囲:**
- 画像 + 音楽 + 漫画 + 小説の解析対応
- 感情選択肢の提示と選択UI
- 3種類の出力形式（SNS投稿、日記、レビュー）での文章生成
- メールアドレス認証によるユーザー管理
- 基本的なパーソナライゼーション（履歴ベース）
- GDPR準拠のデータ削除機能

**MVPに含めないもの:**
- 動画解析
- 高度なA/Bテスト機能
- 多言語対応
